# Гривня — бекенд (v1)

Реальний бекенд для «Гривня»: справжні акаунти, завдання з бази даних, і
**реальна перевірка адміном** замість клієнтського таймера — заявка
користувача не нараховується автоматично, її підтверджує чи відхиляє людина
через панель `/admin`.

Статус виплат залишається чесним: платіжного провайдера ще не підключено,
тож заявки на виведення завжди отримують статус «В обробці» — як і було
домовлено, тут немає і не буде фейкового «Виплачено».

## Що є

- `server.js` — Express-сервер, роздає API та статичні файли з `public/`.
- `db/` — SQLite (вбудований `node:sqlite`, без зовнішніх залежностей для БД),
  схема (`db/index.js`) і каталог завдань (`db/tasks-catalog.js`, `db/seed.js`)
  — той самий набір перевірених завдань, що був у прототипі-артефакті.
- `routes/api.js` — реєстрація/вхід, список завдань, подача на перевірку,
  гаманець, заявка на виведення.
- `routes/admin.js` — вхід адміна (окремий пароль, не повʼязаний з акаунтами
  користувачів) і підтвердження/відхилення заявок.
- `public/index.html` — фронтенд користувача (той самий дизайн, тепер працює
  через API замість localStorage).
- `public/admin.html` — панель перевірки заявок.

## Запуск локально

Потрібен **Node.js 22.5+** (використовується вбудований `node:sqlite`, тому
зовнішня СУБД чи нативні модулі не потрібні).

```bash
npm install
cp .env.example .env   # відредагуй SESSION_SECRET і ADMIN_PASSWORD
node -r dotenv/config server.js   # або просто експортуй змінні з .env у shell
```

Простіше без dotenv:

```bash
npm install
ADMIN_PASSWORD=твій-пароль SESSION_SECRET=довгий-випадковий-рядок npm start
```

Відкрий `http://localhost:3000` — акаунт користувача, і
`http://localhost:3000/admin` — панель перевірки.

База даних — файл `data/grivnya.db` (створюється автоматично, каталог завдань
заповнюється при кожному старті сервера).

## Деплой (щоб сайт став справді публічним)

Я не можу сам виставити це в інтернет — потрібен хостинг і домен, якими
керуєш ти. Найпростіші варіанти для Node-застосунку з файлом SQLite:

- **Railway** або **Render** — підключаєш цей код (через GitHub-репозиторій
  або завантаженням), вони самі ставлять `npm install && npm start`. Обом
  потрібен **постійний диск** (persistent volume/disk) під `data/`, інакше
  база обнулиться при кожному передеплої — увімкни цю опцію в налаштуваннях
  сервісу й вистав `DB_PATH` на шлях усередині цього диска.
- Будь-який VPS (навіть найдешевший) теж підійде — `npm install && npm start`
  за `pm2` або systemd-сервісом, і Nginx/Caddy спереду для домену й https.

В обох випадках обовʼязково постав **свої** `SESSION_SECRET` і
`ADMIN_PASSWORD` через змінні середовища хостингу — не копіюй значення з
`.env.example`.

Якщо захочеш, щоб деплоєм зайнявся я — підключи Railway або Render як
інтеграцію в цьому чаті, і я зможу завантажити код і підняти сервіс прямо
звідси.

## Чого тут ще свідомо немає

- **Реальних виплат.** Щоб гроші з балансу справді йшли людям на картку,
  потрібен зареєстрований ФОП/юрособа і підключений платіжний провайдер
  (LiqPay, Fondy, Stripe тощо) — це не технічна, а юридично-фінансова
  частина, яку маєш оформити ти сам. Поки цього немає, статус «В обробці»
  — єдиний чесний варіант, і я свідомо не показую «Виплачено».
- **Антифрод понад людську перевірку.** Зараз єдиний захист від
  накручування — те, що кожну заявку дивиться людина. Якщо обсяг заявок
  виросте, знадобляться додаткові перевірки (ліміти на акаунт, перевірка
  IP/пристрою тощо) — скажи, коли буде актуально, і я додам.
- **Підтвердження email і відновлення пароля** — зараз реєстрація одразу
  активна, без листа підтвердження; можна додати пізніше.
